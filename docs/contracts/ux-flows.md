# UX Flows Contract (SSOT)

## 목적
- MVP 핵심 사용자 흐름의 화면 단위 동작과 상태 전이를 정의한다.
- 모든 화면은 공통 상태머신과 오류 문구 정책을 따른다.

## 공통 상태머신
- 상태: `loading | success | error | empty`
- 전이 원칙:
  - 첫 진입: `loading`
  - 데이터 수신 성공 + 항목 있음: `success`
  - 데이터 수신 성공 + 항목 없음: `empty`
  - 요청 실패: `error`

## 네트워크 실패/오프라인 공통 규칙
- 읽기 요청 실패:
  - 마지막 캐시가 있으면 캐시를 보여주고 "연결이 불안정합니다." 배너 표시.
  - 캐시가 없으면 `error` 상태 + 재시도 CTA 노출.
- 쓰기 요청 실패:
  - 즉시 재시도 1회 후 실패 시 사용자에게 명확한 실패 메시지.
  - 중복 write 방지를 위해 idempotency key 또는 서버 제약 사용.
- 오프라인 감지:
  - 쓰기 액션 버튼은 "오프라인에서는 제출할 수 없습니다."로 비활성화.
  - 읽기는 캐시 우선으로 표시.
- 재시도 공통:
  - 사용자 수동 재시도 우선.
  - 자동 재시도는 최대 1회, 이후는 명시적 동의 필요.

## 0) 앱 최초 진입/Auth Gate 플로우
- 화면: `앱 시작 -> (auth)/login`
- 흐름:
  1) 앱 부팅 시 세션 확인 (`loading`)
  2) 세션 로딩 완료 전에는 라우팅을 변경하지 않음(초기 race 방지)
  3) 세션 없음 -> 로그인 화면 유지 (`success`)
  4) 세션 있음 + 프로필 존재 -> `(tabs)`로 라우팅
  5) 세션 있음 + 프로필 미완성 -> `signup`으로 라우팅
- 강제 규칙:
  - 로그인 전에는 홈/사연/쇼/마이 탭 접근 불가
  - 딥링크로 tabs 진입 시도도 auth로 리다이렉트
  - 로그인 성공 직후에만 탭 접근 허용
  - 로그인 실패는 `AUTH_INVALID_CREDENTIALS | EMAIL_NOT_CONFIRMED | NETWORK | SESSION_MISSING` 원인별 문구로 표시

## 0.1) 회원가입 분기 플로우 (사연자 vs 뮤지션 신청)
- 화면: `signup`
- 분기:
  - 단계 1: 회원 유형 선택(`viewer | musician`)
  - 단계 2: 계정 정보(`email`, `password`, `passwordConfirm`)
  - 단계 3: 공통 프로필(`nickname`, `age`, `gender`)
  - 단계 4A(viewer): `preferredGenres[]` 멀티 선택
  - 단계 4B(musician): `artist_name` + 샘플곡(`파일 업로드` 또는 `임시 URL`) 중 1개 필수
  - 제출 완료: `signUp -> signInWithPassword -> profile/application 저장 -> /(tabs)` 진입
- UX 규칙:
  - `pending` 상태에서는 업로드 CTA 비활성 + "승인 후 이용 가능" 고정 문구
  - `EMAIL_NOT_CONFIRMED` 발생 시 홈 진입 대신 인증 안내 + 인증 메일 재전송 액션 제공

## 1) 사연 작성 플로우
- 화면: `사연 > 작성`
- 입력: 제목, 본문
- 흐름:
  1) 사용자가 작성 폼 입력
  2) 제출 시 `loading`
  3) RPC `submit_story_rate_limited` 호출
  4) 성공 시 `success` 토스트 후 목록/상세 이동
  5) 실패 시 `error` 메시지 표시
- 권한:
  - 로그인 필수
  - 차단/레이트리밋은 서버 판정
- 익명 UX + PII 방지 가이드:
  - 닉네임/실명/연락처/주소/계좌/이메일 등 식별 정보 입력 금지 안내를 폼 하단에 고정 노출.
  - 입력 중 PII 패턴 탐지 시 사전 경고(클라) + 최종 차단(서버).
  - 차단 문구는 사유를 과도하게 설명하지 않는다.

## 2) 제출 업로드 플로우 (뮤지션)
- 화면: `사연 > 제출` 또는 `마이 > 곡 제출`
- 입력: 오디오(필수), 커버(선택), 메이킹노트(필수)
- 흐름:
  1) 업로드 세션 발급 요청(Edge Function)
  2) 파일 업로드 진행 상태 표시
  3) 완료 후 RPC `complete_song_submission` 호출
  4) 성공 시 `submitted` 상태 카드 표시
  5) 실패 시 업로드/등록 단계별 오류 구분 표시
- `STORAGE_PATH_INVALID` 분기:
  - 업로드 세션 발급: 경로 파라미터 규칙 위반 시 즉시 거부 → 토스트로 userMessage 표시, 세션 재요청 버튼 노출.
  - 업로드 완료: signed URL 경로와 실제 업로드 대상 불일치 시 → 토스트 표시, 업로드 단계부터 재시도 유도.
  - 제출 등록: RPC 호출 시 경로가 `artist/{user_id}/song/{song_id}/...` 규칙 위반 시 → 토스트 표시, 제출 버튼 잠금 해제 후 수정 유도.
- 에러 UI 행동 규칙: `STORAGE_PATH_INVALID` — 토스트로 userMessage 표시, retryable=false이므로 "재시도" 버튼은 세션/업로드 단계 재시작 시에만 노출.
- 권한:
  - `artist` 이상만 허용
  - 파일 접근은 signed URL만 허용

## 3) 결선 쇼 재생 플로우
- 화면: `쇼`
- 흐름:
  1) Top10 목록 조회(`loading -> success/empty/error`)
  2) 트랙 선택 시 재생 URL 요청
  3) URL 수신 후 재생 시작
  4) 만료/권한 오류 시 URL 재요청 또는 오류 문구 표시
- 주의:
  - URL 만료를 고려해 재생 시점 직전 요청 권장
  - 공개 URL 하드코딩 금지

## 3.1) Show 주간 시즌 + 라운드 플로우
- 화면: `쇼`
- 섹션: `예선 | 본선 | 결승`
- 흐름:
  1) 활성 시즌 조회 (`loading`)
  2) 라운드별 트랙 목록 조회 (`success/empty/error`)
  3) 트랙 카드 선택 -> 상세 진입
  4) 상세에서 재생/투표 액션 수행
- empty 문구:
  - "현재 진행 중인 라운드 트랙이 없어요"
- error 문구:
  - "시즌 정보를 불러오지 못했어요. 잠시 후 다시 시도해 주세요."

## 4) 투표 플로우 (1인 3표)
- 화면: `쇼 > 투표`
- 흐름:
  1) 현재 잔여표 조회(힌트 값)
  2) 사용자가 곡 선택 후 투표 실행
  3) RPC `cast_votes_max3` 호출
  4) 성공 시 잔여표 갱신
  5) 실패 시 코드별 메시지 표출
- `DUPLICATE_VOTE` 분기:
  - 중복 클릭: 동일 트랙 투표 버튼 연타로 여러 요청 전송 시 → 토스트로 "이미 투표한 곡입니다." 표시, 해당 버튼 잠금 유지.
  - 재전송: 네트워크 재시도/오프라인 복귀 등으로 동일 `clientRequestId` 요청 재전송 시 → 토스트 표시, 버튼 잠금 해제.
  - 동일 트랙 재투표: 이전에 투표한 곡을 다시 선택해 투표 시도 시 → 토스트 표시, 다른 곡 선택 유도.
- 실패 처리:
  - `VOTE_LIMIT_EXCEEDED`: 잔여표 없음 안내
  - `RATE_LIMITED`: 잠시 후 재시도 안내
  - `AUTH_REQUIRED`: 로그인 유도
  - `DUPLICATE_VOTE`: 이미 투표한 곡 안내(위 분기 적용)
- 에러 UI 행동 규칙: `DUPLICATE_VOTE` — 토스트로 userMessage 표시, retryable=false이므로 재시도 버튼 미노출, 해당 트랙 투표 버튼 잠금 또는 비활성화.
- 부정 방지 UX 규칙:
  - 버튼 연타 방지를 위해 요청 중 버튼 잠금.
  - 디바이스 이상 패턴 감지 시 추가 지연/재인증 안내 노출.
  - 투표 성공/실패 이벤트에 `correlationId`를 로깅해 CS 추적 가능하게 유지.

## 5) 신고 플로우
- 화면: `사연 상세` 또는 `쇼 상세`
- 입력: 신고 사유(필수)
- 흐름:
  1) 신고 사유 입력
  2) 제출 시 RPC `create_report_and_queue`
  3) 성공 시 접수 완료 메시지
  4) 실패 시 코드별 오류 메시지
- 후속:
  - 신고 즉시 검수 큐로 전환되어 댓글 없이 운영 검수 경로로 이동

## 모더레이션 임계치/상태전이 UX 표
| 상태 | 사용자 노출 문구 | 운영 동작 |
|---|---|---|
| `open` | "신고가 접수되었습니다." | 큐 대기 |
| `in_review` | "콘텐츠를 검토 중입니다." | 우선 검수 |
| `resolved` | "운영 정책에 따라 조치되었습니다." | 차단/유지 확정 |
| `dismissed` | "검토 결과 조치가 필요하지 않았습니다." | 오신고 종료 |

| 누적 신고 score | 사용자 반응 | 내부 정책 |
|---:|---|---|
| 1~2 | 접수 완료 | 일반 우선순위 |
| 3~4 | 검토 중 표시 가능 | 검수 우선순위 상향 |
| 5+ | 검토 중(긴급) | 고위험 큐 이동 |

## 금칙어/콘텐츠 차단 에러 문구 규칙
- 원칙:
  - 짧고 안전한 문장
  - 내부 정책/탐지 로직 상세 노출 금지
  - 개선 가능한 행동을 함께 제시
- 템플릿:
  - 기본: "정책상 등록할 수 없는 내용이 포함되어 있습니다."
  - 재작성 유도: "표현을 수정한 뒤 다시 시도해 주세요."
  - 반복 위반: "잠시 후 다시 시도해 주세요."
- 금지:
  - 탐지 키워드/스코어 공개
  - 운영 내부 판단 기준 상세 설명

## 화면별 상태/예외/빈 상태 체크리스트
| 화면 | loading | success | empty | error | 예외 |
|---|---|---|---|---|---|
| 사연 목록 | 스켈레톤 3개 | 목록 렌더 | "아직 사연이 없습니다." | 재시도 버튼 | 차단 항목은 목록 비노출 |
| 사연 작성 | 제출 중 버튼 잠금 | 완료 토스트 후 이동 | 해당 없음 | 코드별 에러 문구 | PII 감지 시 제출 차단 |
| 제출 업로드 | 업로드 진행률 | 제출 완료 카드 | 해당 없음 | 단계별 오류 | URL 만료 시 재발급 |
| 쇼/재생 | 탑10 로딩 | 재생 가능 | "공개된 곡이 없습니다." | 재시도 | URL 만료/권한 변경 |
| 투표 | 잔여표 로딩 | 잔여표 갱신 | 해당 없음 | 코드별 에러 | 3표 초과/중복/쿨다운 |
| 신고 | 제출 중 | 접수 완료 | 해당 없음 | 오류 안내 | 동일 대상 반복 신고 제한 |

## 결정 근거
- UX 문서에 운영 정책(부정 방지/모더레이션/PII 차단)을 직접 반영해 화면 구현 시 누락을 줄인다.
- 상태/예외/빈 상태를 표준화해 QA가 기능별 판정 기준을 빠르게 공유하도록 한다.
