# PR05 Execution Log - 재생 signed URL 활성화 + 만료/권한 오류 처리

## 목표
- Show 상세 화면에서 signed URL 기반 오디오 재생을 실제로 활성화.
- URL 만료/권한 오류를 사용자 메시지로 분기하고, 만료성 실패는 1회 자동 재요청.
- signed URL은 UI/로그에 노출하지 않고 `correlationId`만 개발 로그로 추적.

## 변경 파일
- `app/show/[id].tsx`
- `features/show/api/mutations.ts`

## 구현 요약
1) 재생 활성화(`app/show/[id].tsx`)
- `expo-av`로 `Audio.Sound` 인스턴스를 생성/정지/해제.
- 언마운트 시 `stopAsync` + `unloadAsync`로 리소스 정리.
- 재생 전 `get-track-play-url` 호출 후 받은 URL로 즉시 재생 시작.

2) 만료/권한 오류 처리
- 재생 시작 실패 메시지에서 만료/권한성 키워드가 감지되면 signed URL 재요청을 1회 수행.
- 재요청 후 재생 성공 시 안내 문구 표시.
- 재요청 후에도 실패하면 표준 재생 실패 문구를 노출.

3) 권한/인증 매핑 보강(`features/show/api/mutations.ts`)
- `get-track-play-url` 응답 HTTP 401/403을 각각 `AUTH_REQUIRED`/`FORBIDDEN_ROLE`로 명시 매핑.
- 토큰이 없을 때 잘못된 `Bearer anonKey`를 보내지 않도록 Authorization 헤더를 조건부로만 설정.

## 검증
- 정적 진단:
  - `ReadLints` 기준 변경 파일 린트 에러 없음.
- 수동 점검 체크리스트:
  - 상세 화면에서 `재생` -> `정지` 토글 동작.
  - 권한 없음/세션 없음 상태에서 코드별 사용자 메시지 분기.
  - 만료성 실패 시 1회 URL 재요청 후 복구 시도.
- 참고:
  - 절전/세션 중단 이슈로 CLI 기반 실측은 재개 세션에서 수행했고, 장기 실행 터미널은 종료 상태를 확인함.
