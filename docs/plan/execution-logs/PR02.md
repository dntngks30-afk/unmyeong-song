# PR02 Execution Log - 회원가입 분기 + 신청 저장

## 목표
- 회원가입/프로필 완료를 `viewer` vs `musician 신청`으로 분기한다.
- 프로필 저장과 뮤지션 신청 저장을 DB에서 수용할 스키마/RLS를 추가한다.
- My 탭에서 pending 상태를 표시하고 승인 전 업로드를 차단한다.

## 변경 파일
- `supabase/migrations/202602170003_signup_profile_application.sql`
- `supabase/policies/09_musician_applications_rls.sql`
- `app/(auth)/signup.tsx`
- `app/(tabs)/my.tsx`

## 구현 요약
1) DB/RLS
- `application_status` enum 추가 (`pending|approved|rejected`).
- `profiles` 확장 컬럼 추가: `nickname`, `age`, `gender`, `favorite_genre`.
- `musician_applications` 테이블 생성 + 인덱스 + `updated_at` 트리거.
- RLS 정책:
  - 본인 insert
  - 본인/관리자 select
  - 관리자 update(승인/거절)

2) FE 회원가입 분기
- 세션 없음: 계정 생성(email/password) 단계.
- 세션 있음 + 프로필 미완성: 프로필 저장 단계.
- 분기:
  - `viewer`: profiles upsert 저장
  - `musician`: profiles upsert + `musician_applications(status=pending)` 저장

3) My 탭 가드
- `profiles.role`과 최신 `musician_applications.status`를 조회.
- `pending`이면 승인 대기 문구 표시.
- `role != artist`면 제출 버튼 비활성.

## 검증
- 타입체크: `npx tsc --noEmit` 실행
- 수동 점검(계약 기준):
  - 세션 없음 시 계정 생성 화면 노출
  - 세션 있음 + 프로필 없음 시 분기 저장 가능
  - 뮤지션 신청 저장 후 My 탭 pending 문구/업로드 차단 표시
