# PR06 Execution Log - 승인된 뮤지션 업로드 게이트 + mp3 제출 검증

## 목표
- 제출 업로드 플로우를 승인된 뮤지션(또는 관리자)에게만 허용.
- 오디오 업로드의 클라이언트 선검증(mp3, 10MB 제한) 추가.
- 제출/세션 발급에서 인증 누락 시 즉시 `AUTH_REQUIRED`로 차단.

## 변경 파일
- `features/submission/model/types.ts`
- `features/submission/api/mutations.ts`
- `app/submission/new.tsx`
- `app/(tabs)/my.tsx`

## 구현 요약
1) 권한 게이트
- `app/submission/new.tsx`에서 세션/프로필/신청 상태를 로드.
- 허용 조건:
  - `admin`, 또는
  - `artist` + `application_status=approved`(신청 이력이 없는 기존 artist는 허용)
- 미충족 시 제출 시도 전 사용자 안내 후 중단.

2) 업로드/제출 인증 강화(`features/submission/api/mutations.ts`)
- `createUploadSession`, `completeSongSubmission`에서 access token이 없으면 즉시 `AUTH_REQUIRED`.
- Authorization 헤더는 실제 사용자 토큰만 사용(anon fallback 제거).
- 환경변수 로딩을 `getEnv()` SSOT 유틸로 통일.

3) 오디오 파일 규격 선검증
- `LocalFileInput`에 `kind`를 추가해 audio/cover를 구분.
- 오디오 업로드 전:
  - 파일명 `.mp3` 확장자 검사
  - blob size `<= 10MB` 검사
- 위반 시 `STORAGE_PATH_INVALID` 계열 사용자 메시지로 즉시 차단.

4) My 탭 진입 조건 정렬
- `app/(tabs)/my.tsx`의 제출 CTA 활성 조건을 승인 게이트와 동일 규칙으로 정렬.

## 검증
- 수동 체크리스트:
  - 승인되지 않은 계정에서 제출 시도 차단.
  - 오디오 확장자 비정상/용량 초과 시 업로드 전 차단.
  - 정상 계정/정상 파일에서 세션 발급 -> 업로드 -> 제출 완료 경로.
- 정적 진단:
  - 변경 파일 린트 에러 여부를 후속 검증 단계에서 재확인.

## 비고
- 실제 디바이스 파일 선택기 연동 전 단계로 URI 직접 입력 흐름을 유지함.
- 서버 최종 강제(RPC/Storage 정책)와 함께 클라이언트 선검증을 병행해 실패를 조기 안내하도록 구성함.
